## Decision

Settings, organization administration, and platform administration keep their
current routes, information architecture, permissions, and data-heavy content.
They adopt the main workspace's shared shell and sidebar primitives,
typography, spacing, focus behavior, and responsive navigation. The current
self-hosted web deployment is single-tenant, so live management routes omit the
organization switcher while retaining platform administration for future
multi-tenant deployments.

## Findings considered and rejected

- **Keep the separate management sidebar and adjust only its colors**:
  rejected because both surfaces already use the same `--berry-*` colors. The
  mismatch comes from separate structure, sizing, responsive behavior, and
  interaction code.
- **Replace management screens with the chat layout**: rejected because
  settings, tables, policy controls, and analytics need page and section
  hierarchy that a conversation surface does not provide.
- **Redesign every administration screen individually**: rejected because the
  shared `ManagementPage`, `Section`, and table primitives provide a smaller
  and safer consolidation boundary.
